# Beam in a Fluid Tunnel — Large-Deflection FSI Validation

## Overview
This tutorial reproduces **Case 1 of section 6.4 of Zhang, Liu & Khoo (2012)**: a
soft, slender cantilever beam clamped to the bottom wall of a channel and bent
over by a viscous, low-Reynolds-number channel flow. It is a standard
fluid–structure interaction (FSI) benchmark for large elastic deflection.

The fluid is solved with `pimpleFoam`. The beam is a finite-volume Simo–Reissner
beam (`coupledTotalLagNewtonRaphsonBeam`) advanced through the
`sixDoFRigidBodyBeamMotion` motion solver, and the two are coupled with an
**actuator-line (ALM) drag model**:

- the beam reads an upstream fluid velocity and computes a quasi-steady drag
  force per control volume (`almDrag` momentum contribution), and
- that force is smeared back into the fluid momentum equation by the
  `beamActuatorLine` fvOption.

The beam mesh does not move within the fluid mesh; the ALM is the only two-way
coupling. This is the same coupling used by the `flexibleStem` and leaflet
validation cases.

---

## Requirements
This case is **not runnable with `beamFoam` on its own**. `beamFoam` provides the
finite-volume beam solver, but the fluid–beam (ALM) coupling used here — the
`sixDoFRigidBodyBeamMotion` motion solver with the `finiteVolumeBeam` restraint
and the `beamActuatorLine` fvOption — is provided by **moorFV**, which builds on
`beamFoam`. Obtain and compile moorFV (which pulls in `beamFoam`) and run this
tutorial from there:

> **moorFV:** https://github.com/solids4foam/moorFV

## Case Layout
```
beamTunnel/
├── Allrun                     # top-level driver: initialise beam, then run FSI
├── Allclean                   # cleans both sub-cases
├── beamInitialisation/
│   └── beam_0/                # stage 1: build the beam mesh + reference config
└── beamTunnel/                # stage 2: the coupled fluid + beam case
    ├── 0_orig/                # pristine fluid fields (U, p, pointDisplacement)
    ├── constant/              # transport, turbulence, motion/restraint dicts
    └── system/                # blockMeshDict, fvOptions (ALM), solver settings
```

`beamInitialisation/beam_0` is a standalone, fluid-free step that builds the
beam. The top-level `Allrun` runs it, copies the resulting beam mesh into
`beamTunnel/beamTunnel/constant/beam_0` and its initial fields into
`beamTunnel/beamTunnel/0_orig/beam_0`, and then runs the coupled case.

> **Note on `0_orig`.** OpenFOAM conventionally names the pristine field
> directory `0.orig`, but this repository's `.gitignore` ignores `*.orig`, so it
> is named `0_orig` here. Only the fluid templates (`U`, `p`,
> `pointDisplacement`) are version controlled; the beam fields staged into
> `0_orig/beam_0` at run time are git-ignored and regenerated by `Allrun`.

## Geometry
| Quantity | Value |
|---|---|
| Tunnel length `L` | `0.04 m` (`x ∈ [0, 0.04]`) |
| Tunnel height `H` | `0.01 m` (`y ∈ [0, 0.01]`) |
| Beam cross-section `b × h` | `0.0004 × 0.0004 m` (square) |
| Beam length | `0.008 m`, `80` control volumes |
| Beam root | clamped to the bottom wall at `x = 0.01 m`, rising in `+y` |
| Background mesh | `150 × 38 × 1` (`blockMesh`), one cell in `z` (2-D) |

`beamInitialisation` builds the beam straight along `x`, then
`setInitialPositionBeam` translates it to `(0.01, 0, 0)` and rotates it `90°`
about `z` so it stands upright, rooted on the lower wall.

```
 y = H = 0.01   ────────────────────────────────────── upperWall (symmetry)
                                    ┊
   parabolic  →                     ┊ beam (0.008 m, 80 CVs)
   inlet      →                     ┊ bends downstream
              →                     ┊
 y = 0        ──────────────────────┴───────────────── lowerWall (no-slip)
              x = 0        x = 0.01 (beam root)        x = 0.04
```

## Fluid and Beam Properties
**Fluid** (`constant/transportProperties`) — note this is *not* water; the
viscosity is paper-specified:
- Kinematic viscosity `ν = 1e-5 m²/s`, density `ρ_f = 1000 kg/m³`
  (dynamic viscosity `μ = 0.01 Pa·s`)
- Peak inlet velocity `U_max = 0.015 m/s`, so `Re_h = U_max·h/ν ≈ 0.6`
  (viscous-dominated, Stokes-like)

**Beam** (`beamInitialisation/beam_0/constant/beamProperties`):
- Young's modulus `E = 1e4 Pa`, shear modulus `G = 3846 Pa` (`ν ≈ 0.3`)
- Density `ρ_s = 7800 kg/m³`, fluid density for buoyancy `1000 kg/m³`
- Model `coupledTotalLagNewtonRaphsonBeam`, rectangular cross-section

---

## Boundary Conditions (fluid)
- **`inlet`:** `codedFixedValue` parabolic profile, applied as a step at
  `t = 0`. In SI form `Uₓ(y) = -150 y² + 3 y  [m/s]` (Zhang 2012 in CGS:
  `1.5(-y² + 2y) cm/s`), giving `U_max = 0.015 m/s` at the top.
- **`outlet`:** `pressureInletOutletVelocity`.
- **`upperWall`:** `symmetry` (paper: `v = 0` at the top).
- **`lowerWall`:** `noSlip` (the beam root is clamped here).
- **`frontAndBack`:** `symmetry` (the case is effectively 2-D, one cell in `z`).

---

## Coupling
**Motion solver** (`constant/dynamicMeshDict`): `dynamicMotionSolverFvMesh` with
`sixDoFRigidBodyBeamMotion`. The body carries a `finiteVolumeBeam` restraint that
fires `beam.evolve()` once per time step to advance the structure. `fixedPoint`
and `fixedOrientation` constraints hold the mesh still — the motion solver exists
only to drive the beam.

**ALM drag** (`beamInitialisation/beam_0/constant/beamMomentumContributionProperties`):
- Drag coefficients `Cdn = 26`, `Cdt = 0.01`
- Upstream sampling at `samplingRadius × almSamplingReferenceLength =
  30 × 0.000106 ≈ 3.18 mm` upstream of each beam node, along `(-1 0 0)`
- `almDragReferenceLength = 0.0004 m` (= beam thickness)

**Force projection** (`system/fvOptions`): `beamActuatorLine` smears the beam
force into the fluid with Gaussian width `ε = 6e-4 m` and `ρ = 1000 kg/m³`.

The ALM force is sampled once per time step (frozen during the structural
Newton loop and the PIMPLE loop): this is explicit partitioned FSI.

---

## Numerical Setup
- **Fluid:** `pimpleFoam`, `Δt = 1e-4 s`, `t_end = 2.5 s`, `maxCo = 0.1`
  (fixed `Δt`), write every `0.1 s`.
- **Beam Newton–Raphson:** `residualTol = 1e-9`, `solutionTol = 1e-10`,
  `absoluteTol = 1e-10`, up to `500` correctors.
- **Decomposition:** 2 subdomains — the fluid with `scotch`, the beam with a
  `manual` map that keeps the whole beam on processor 0 (see below).

## Running the Case
```
./Allclean
./Allrun
```
`Allrun` initialises the beam and then runs the coupled case in **parallel on 2
cores**. Progress for the initialisation stage is logged to
`log.beamInitialisation`, and the coupled run to
`beamTunnel/beamTunnel/log.pimpleFoam`.

**Decomposition.** The fluid region is split into 2 subdomains with `scotch`.
The beam region uses a `manual` decomposition read from
`constant/cellDecomposition.beams` — a `labelList`, one entry per beam control
volume (80 here), giving the processor each beam cell belongs to. All entries
are `0`, so the entire beam is kept on processor 0 while the fluid is split
across both; the actuator-line coupling exchanges data between them. This map is
tied to the beam mesh: if you change `nSegments` in `beamProperties`, regenerate
it with the matching length. The core count is set by `numberOfSubdomains` in
both `system/decomposeParDict` (fluid) and `system/beam_0/decomposeParDict`
(beam) — keep them equal. To run serially instead, see the commented note at the
end of `beamTunnel/beamTunnel/Allrun`.

---

## Post-processing
`Allrun` finishes by extracting the beam tip streamwise displacement into
`beamTunnel/beamTunnel/tipDisplacement.dat` (via `extractTipDisplacement.sh`,
which reads the `x`-component of `W` on the beam's `right` patch at each written
time) and plotting it to `tipDisplacement.pdf` with `tipDisplacement.gnuplot`.
Both can also be run by hand after a run:
```
cd beamTunnel/beamTunnel
./extractTipDisplacement.sh        # writes tipDisplacement.dat (time, W_x)
gnuplot tipDisplacement.gnuplot    # writes tipDisplacement.pdf
```
- Open `case.foam` in **ParaView** and use **WarpByVector** on `pointW` to
  visualise the deformed beam (the beam mesh carries its displacement in
  `pointW`; the cells themselves stay put).

---

## Expected Results
The beam bends downstream and reaches a steady tip `x`-displacement after
`t ≈ 1.5 s`. Reference steady-state values span roughly **4.5–5.2 mm** across
the literature (Zhang 2012 IS-FEM ≈ 5.2 mm; Han 2020/2021 ≈ 4.5–4.6 mm), and the
present ALM setup lands within about 10% of that band. The result is sensitive
(≈ 20%) to the ALM kernel width `ε` and the upstream sampling distance, which
together act as an effective calibration of the quasi-steady drag closure — the
independently calibrated quantity is `Cdn`.
