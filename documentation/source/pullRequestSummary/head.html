1. Overview

Timeline

{{TIMELINE}}

What the branches add, in brief

  • 2025, beamFoam (Seevani Bali, Philip Cardiff, Amirhossein Taran).
    • New: cross-section classes for v2306, one createBeamMesh utility, four function objects (convergence, displacements, energy, forces/moments), per-beam material properties, and a beamMomentumContribution framework (Morison drag, ground contact).
    • Solver changes: a linear spring boundary condition with a time-varying offset force, a refactored solver with d2dt2 scheme names and normalised residuals, and a fix to the Euler inertia terms.
    • Removed: unused contact, pulley, plasticity, bunching and boundary-condition code.
    • Repository: OFW-paper tutorials, READMEs, a GitHub Actions build and Allwmake fixes.
  • February – August 2026 (Colm, with Codex).
    • Six rigid-body unknowns appended to the BlockEigen system, and rigid-body step data passed from moorFV.
    • A "staged" and an experimental "fullyImplicit" coupling mode, history files, efficiency plots and interFoam cases.
    • In effect still a partitioned scheme: the body block is an identity, and FvBeamNewmark recomputes the body state afterwards.
  • 30 September – 1 October 2026 (Colm, with Claude).
    • A review of the earlier path and a development plan.
    • Phase 0: the rigidBodyEnd body inside beamFoam, plus two bug fixes.
    • Phase 1: monolithic translation in BlockEigen. Phase 2: rotation.
    • Phase 3: moorFV's beamFoamCoupled solver.
    • Phase 4: validation and stress tests in interFoam.

3. moorFV: net changes

All moorFV changes, branch point to now (the beamFoam submodule pointer is listed as src/beamFoam):

{{MF_NET}}
  • New sixDoF solver beamFoamCoupled (sixDoFFvBeamSolvers/beamFoamCoupled/, 36393fb). The fluid force and moment (with the weight) and any other restraints form the applied load. beamFoam solves the beam and the body together, and the state it returns is copied into the motion without recomputation or relaxation.
  • finiteVolumeBeam restraint.
    • solveMonolithic() (36393fb).
    • Earlier: RigidBodyStepData is passed to the beam, there are beamAttachmentKinematics and blockEigenAuthoritativeMotion options, and the attachment force has a history file (d72ed0a, 3dc0bb1, ffa51e3).
  • Interface change. sixDoFRigidBodyMotionFvBeamRestraint::restrain() takes a non-const motion.
  • Base solver accessors: restraints(), constraints(), initialCentreOfRotation(); sixDoFRigidBodyMotionFvBeam gains applyBlockEigenSolution() and state0().
  • Build. Make/options include beamFoam headers through $(BEAMFOAM_DIR) (74005ba), replacing hard-coded paths.
  • Open points from the review:
    • The acceleration relaxation in updateAcceleration also applies on the first outer corrector of each step (static bool first).
    • main has renamed sDoFRGBFvBeam, so the branch must be rebased.
    • The displacement*.dat file holds the anchor displacement.
