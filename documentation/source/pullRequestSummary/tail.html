6. Phase 5: several mooring lines (plan)

The problem

  • Only one line is supported. The monolithic coupling adds the body's six unknowns to one beam's BlockEigen system, and beamFoamCoupled stops if the body has a second finiteVolumeBeam restraint.
  • The target case has four. mooringCase-H12T20 has four lines (beamone … beamfour). Each is a separate restraint with its own beam region and its own beamModel (finiteVolumeBeam.C:65–70, beamModel::New per restraint), so it has its own mesh and its own linear system. The body is a 3.144 kg floating box in waves. It runs with FvBeamNewmark, accelerationRelaxation 0.7 and 3 outer correctors.

Two ways to couple several lines

ApproachHowTrade-offs
A. One combined matrix Put every line and the body in one sparse system: body columns on each line's end cell, with the body rows summing all attachment forces. Easiest if all lines live in one beamFoam region, which beamFoam already supports for several beams via cell zones (nBeams > 1 in the CQ_/CM_ set-up). Reuses the Phase 1–2 code almost unchanged. But the case must be rebuilt with one beam region; the system grows with every line; it is serial; and all lines share one Newton loop.
B. Static condensation (recommended) Each line keeps its own system. It is reduced to a 3×3 stiffness and a 3-vector residual at its attachment, and the body solves a 6×6 system with all lines' contributions. Each line then back-substitutes. This is the same Newton step as A, without approximation. Keeps the current one-restraint-per-line set-up. Cost grows linearly with the number of lines, and lines can later run on different processors. A single line reproduces today's results. Needs a refactor of the coupling interface.

Static condensation, in equations

The attachment is a pin, so each line passes only a force to the body.

  • Partition. Split line i's Newton unknowns into its interior, Δui, and its attachment displacement, Δwi (3 components). Its linear system is then:
    [ Kuu Kuw ; Kwu Kww ] [ Δui ; Δwi ] = − [ ru ; rw ]
  • Condense. Eliminating the interior gives the line's effective stiffness and residual at its attachment:
    Si = Kww − KwuKuu−1Kuw,    r̃i = rw − KwuKuu−1ru
    Both need only the factorisation BlockEigen already computes, plus three extra back-substitutions (the columns of Kuu−1Kuw).
  • Compatibility. Each attachment moves with the body. With body unknowns Δq = (Δx, Δθ) and arm ri (from refAttachmentPt):
    Δwi = Ti Δq,   Ti = [ I   −spin(R ri)·T(θ) ]
    These are the same terms as the Phase 2 rotation columns.
  • Body step. The 6×6 body system sums every line's contribution:
    ( Kbody + Σi TiT Si Ti ) Δq = − ( Rbody + Σi TiT r̃i )
  • Back-substitution. Each line recovers its interior update: Δui = − Kuu−1( ru + Kuw Ti Δq ).

Kbody and Rbody are the existing rigidBodyEnd residuals and Jacobians (inertia, gyroscopic, damping, applied load). Only the beam force term changes, from one line to a sum over lines.

Implementation steps

  1. Tidy first. Remove the earlier staged / fullyImplicit path, and fix the tutorial CQ/CM override and the missing abort. Then only one coupling path needs to change.
  2. BlockEigen. Add a way to return the condensed attachment block (Si, r̃i) from the current factorisation, and to finish the line's Newton update for a given attachment increment Δwi. The current appended body rows become the single-line special case.
  3. beamModel interface. Replace "evolve with the body inside" with steps a coordinator can call: assemble and condense, apply attachment increment, report convergence.
  4. Coordinator. Move the body state and Newton loop out of a single beam into a coordinator that owns rigidBodyEnd; moorFV's beamFoamCoupled is the natural home. It collects every finiteVolumeBeam restraint and, at each Newton iteration:
    1. has each line assemble and condense;
    2. builds and solves the 6×6 system;
    3. back-substitutes;
    4. checks convergence of the body and every line.
  5. Diagnostics. Add a per-line Jacobian check (finite differences of the condensed 6×6 tangent), extending jacobianCheck.
  6. Parallel. Keep every line on the master process at first, as now (Pstream::master() in applyRestraints and update, then Pstream::scatter of the state). Later, lines can be spread over processors: only Si and r̃i (12 numbers per line) need a sumOp reduction, and Δq a broadcast.

Validation

  • One line: the condensed path reproduces the current monolithic results to round-off. That covers the 54 rigidBodyEnd checks and the rigidBodyAndBeam_beamFoamCoupled interFoam case.
  • Standalone beamFoam with several lines:
    • two symmetric lines, where the vertical frequency must be √(Σk/m);
    • a four-line spread mooring with an offset, compared with converged partitioned coupling;
    • a line going slack.
  • mooringCase-H12T20: monolithic with 1–3 outer correctors against FvBeamNewmark with converged correctors. Pass: the 4-line case runs monolithically and matches the converged partitioned run.

Things to watch

  • Fluid added mass. The H12T20 body floats in water, and the fluid force is still explicit. Expect to keep 2–3 outer correctors with moveMeshOuterCorrectors yes. What Phase 5 removes is the beam–body splitting and the need for accelerationRelaxation.
  • Slack lines. Si tends to zero when a line is slack. The body system stays well posed through its inertia term m/(βΔt²).
  • Seabed contact (groundContact) only changes the line's own Kuu, so condensation still applies.
  • Restarts. The coordinator must write and read the body state; rigidBodyEnd has no restart support yet.
